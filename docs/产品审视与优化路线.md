# 社易管（SmartSociety）手机端产品审视与优化路线

> **版本：V4.0 产品重构规划**  
> **审视对象：`mobile/Application` 手机端（Flutter + HarmonyOS）及其直接依赖的云端能力**  
> **审视日期：2026-08-17**  
> **目标：不是继续堆功能，而是把“社易管”从一个已有成员/项目/公告/财务能力的管理工具，升级为真正面向社会团体、公益组织、行业协会、基金会及其他非营利组织的移动组织操作系统。**

---

## 0. 本次审视结论

当前项目已经具备较完整的业务骨架：多组织、成员、项目/任务、通知、审批、社会团体会计、预算、钉钉同步、离线同步以及工作台等均已落地；仓库也明确以 Flutter + HarmonyOS 混合方式承载手机端。fileciteturn15file0L2-L2

但从“真实社会团体日常使用”的角度看，当前产品仍明显偏向 **“行政管理 CRUD + 财务工具”**，而不是 **“组织运营平台”**。当前首页虽然已有统计卡、我的任务、财务概览、预算预警、快捷入口和最近项目/通知，但信息仍是把各模块的摘要拼在一起，没有形成围绕“今天组织需要处理什么”的行动中心。fileciteturn16file0L2-L2

当前手机端主导航为 **首页 / 成员 / 项目 / 通知 / 财务** 五栏，路由层已经采用 `StatefulShellRoute.indexedStack`；审批、报表、设置、组织切换等作为二级页面存在。fileciteturn16file0L2-L2 fileciteturn16file0L2-L2

### 核心判断

**P0 不是再增加一个列表页，而是进行一次“组织工作台 + 社会团体运营模型 + UI 信息架构”的重构。**

优先级判断如下：

| 领域 | 当前评价 | 优先级 | 结论 |
|---|---|---:|---|
| 手机端信息架构 | 6/10 | P0 | 五栏可用，但不符合社会团体“工作/协作/治理”心智 |
| 首页工作台 | 6/10 | P0 | 有数据，没有行动闭环 |
| 社会团体能力 | 6/10 | P0 | 会计较强，治理、会员服务、会议、证照、年检、捐赠、志愿者、活动不足 |
| 成员管理 | 6.5/10 | P1 | CRUD 完整，但缺会员生命周期和关系管理 |
| 项目管理 | 7/10 | P1 | 已有任务看板，但缺活动/项目运营闭环 |
| 通知 | 6/10 | P1 | 更像公告箱，不像组织消息中心 |
| 财务 | 8/10 | P0/P1 | 会计深度较好，但移动端信息呈现仍偏“报表工具” |
| 审批 | 6/10 | P0 | 已有引擎，但尚未成为统一工作流中心 |
| UI | 6/10 | P0 | M3/卡片化基础已改善，但层级、密度、入口仍需重构 |
| 权限/治理 | 5/10 | P0 | 社会团体必须从“管理员”升级到正式治理模型 |
| 离线/同步 | 6/10 | P1 | 已有基础，但缺冲突、版本、可解释同步状态 |
| 数据/智能化 | 4/10 | P2 | 当前基本没有组织洞察层 |

# 一、产品定位重构

## 1.1 从“社团管理工具”升级为“社会组织运营平台”

产品应形成三层定位：

### 第一层：组织基础设施

- 组织身份与证照
- 组织架构
- 会员/成员档案
- 角色与权限
- 通讯录
- 组织公告
- 操作审计

### 第二层：组织运营

- 活动
- 项目
- 任务
- 报名
- 签到
- 志愿服务
- 会议
- 会议纪要
- 审批
- 文档
- 通知
- 组织日历

### 第三层：社会团体治理

- 会员大会
- 理事会
- 监事会
- 任期与换届
- 议案/决议
- 财务审批
- 印章/证照
- 年检/年报
- 捐赠与资助
- 资产管理
- 合同管理
- 风险与合规
- 年度工作报告
- 年度预算/决算

**产品最终应让“会长、秘书长、财务、理事、会员、志愿者”都能找到自己的工作入口，而不仅仅是让管理员管理数据。**

# 二、手机端信息架构重大调整

## 2.1 当前五栏的问题

当前底部导航固定为：首页、成员、项目、通知、财务。该结构适合“内部行政管理”，但社会团体真正高频动作往往是：

> 今天有什么活动？我有哪些待办？有哪些审批？会议在哪里？会员发生了什么？本月财务怎样？有哪些风险？

因此建议将导航改为：

### 推荐最终导航

**工作台｜组织｜活动｜协作｜我的**

其中“协作”进入统一工作中心，“组织”成为社会团体核心入口。

| 一级 Tab | 核心内容 |
|---|---|
| 工作台 | 今日事项、审批、活动、任务、财务、提醒、组织动态 |
| 组织 | 会员、组织架构、治理、会议、证照、文档、统计 |
| 活动 | 活动、报名、签到、志愿服务、活动复盘 |
| 协作 | 项目、任务、审批、公告、消息、日历 |
| 我的 | 我的身份、待办、参与记录、设置、组织切换 |

### 对现有模块的迁移

- 成员 → 组织 > 会员
- 财务 → 工作台 > 财务入口 + 组织 > 财务治理
- 项目 → 协作 > 项目
- 通知 → 协作 > 消息/公告
- 审批 → 协作 > 待办
- Profile → 我的
- 设置 → 我的 > 设置

**不要直接删除旧功能；第一阶段允许保留旧路由，通过新的入口映射过去。**

# 五、P0：社会团体治理模型

这是整个项目最重要的新增能力。

## 5.1 治理架构

现有社会团体角色已经包括：会长、副会长、秘书长、理事、监事长、监事。fileciteturn15file0L2-L2

下一步不能只把这些角色当作“权限标签”，必须建立正式治理关系：

```text
组织
├── 会员大会
├── 理事会
│   ├── 会长
│   ├── 副会长
│   ├── 秘书长
│   └── 理事
└── 监事会
    ├── 监事长
    └── 监事
```

## 5.2 任期管理

每个治理职务增加：

- 任职开始日期
- 任职结束日期
- 任期届次
- 是否连任
- 任命/选举依据
- 任职文件
- 状态：在任 / 离任 / 待任

首页自动提醒：

> “秘书长任期还有 38 天到期。”

## 5.3 会议治理

新增会议对象：

- 会员大会
- 理事会
- 常务理事会
- 监事会
- 工作会议

会议能力：

- 创建会议
- 议程
- 参会人员
- 通知
- 回执
- 签到
- 议案
- 表决
- 会议纪要
- 决议
- 附件
- 会后任务

### 会议 → 决议 → 任务闭环

例如：

> 理事会通过“年度公益项目预算” → 自动生成财务审批 → 自动生成项目 → 自动生成负责人任务。

这是社会团体区别于普通项目管理软件的关键能力。

# 十四、P0：权限与治理必须服务端化

当前产品已有角色体系，但权限不能停留在前端页面控制。现有文档也已指出业务级权限仍需要服务端角色矩阵。fileciteturn12file0L2-L2

## 14.1 权限维度

权限应由：

> 角色 × 模块 × 数据范围 × 操作 × 状态

# 三十二、最终产品验收标准

当以下问题都能在手机上直接回答时，才认为“社会团体版本”真正完成：

1. **我今天需要处理什么？**
2. **有哪些审批等我？**
3. **最近有什么活动？谁报名了？谁签到？**
4. **会员有没有欠费？谁最近不活跃？**
5. **理事会什么时候开？有哪些议案？**
6. **上次会议的决议执行了吗？**
7. **本年度预算用了多少？**
8. **有哪些支出待审批？**
9. **组织有哪些证照/年检事项快到期？**
10. **项目到底产生了什么社会成果？**
11. **谁修改过重要数据？**
12. **组织现在是否健康？最大的风险是什么？**

如果只能回答“有多少成员、多少项目、多少通知、多少钱”，产品仍然只是管理工具；如果能回答以上 12 个问题，才开始成为真正的社会团体运营平台。

# 三十三、对当前路线的调整原则

现有路线中已经完成的工作台、通知、项目看板、财务结账/反结账、成员 CSV 等继续保留，不推翻已有成果。fileciteturn12file0L2-L2

但后续开发必须遵守以下规则：

1. **不再以“新增一个页面”为主要交付单位。**
2. **所有新功能必须挂接到组织生命周期。**
3. **社会团体治理能力优先于一般 CRUD。**
4. **财务、审批、会议、项目、活动必须能互相引用。**
5. **所有关键业务必须具备状态、权限、审计和历史。**
6. **手机端优先考虑“快速判断 + 快速处理”，复杂报表提供专业模式。**
7. **先完成数据模型和权限，再做 AI。**
8. **先统一 Design System，再继续大规模页面开发。**
9. **所有 P0 必须同时考虑云端 API、Flutter Provider、路由、缓存、同步和 UI。**
10. **社会团体不是“学校社团 + 财务”的增强版，而应成为独立的一等产品模型。**

## 结论

当前 `smart_society` 已经越过“能不能做”的阶段，进入“产品模型是否正确”的阶段。

现有工程基础已经足以支撑下一轮升级：Flutter 业务层、HarmonyOS 原生壳、AGC Serverless、Provider、go_router、Hive 同步和社会团体会计均已形成基础设施。fileciteturn15file0L2-L2

**下一阶段不建议继续沿着“成员 → 项目 → 通知 → 财务”四条孤立业务线扩张。**

应该转向：

> **组织治理 → 会员 → 会议 → 决议 → 活动 → 项目 → 审批 → 财务 → 成果 → 年度报告**

并通过统一工作台、统一待办、统一消息、统一权限和统一审计把这些能力连接起来。

这将是 `SmartSociety V4` 从“社团管理 App”走向“社会团体数字化运营平台”的核心路线。
