# 跨端统一用户身份与唯一标识规范

> SmartSociety Web / Android / HarmonyOS 三端统一身份规范，属于 `产品审视与优化路线.md` 的 P0 架构要求。

## 1. 核心原则

SmartSociety 必须建立与具体客户端、设备和登录方式无关的内部用户唯一标识。

三端不得分别生成业务用户 ID，也不得使用手机号、邮箱、设备 ID 或某一种第三方登录 ID 直接作为业务主键。

统一采用：

```text
userId
```

作为 SmartSociety 全平台唯一、稳定、不可变的用户身份主键。

## 2. 四层身份模型

```text
ExternalIdentity
       ↓
     userId
       ↓
    Person
       ↓
OrganizationMembership
```

### User

代表系统身份：

```text
User
├── userId              ← 全系统唯一、永久稳定的内部身份 ID
├── status
├── createdAt
├── updatedAt
└── ...
```

### Person

代表自然人主档案：

```text
Person
├── personId             ← 自然人主档案 ID
├── name
├── ...
```

`personId` 与登录身份不同，不应作为认证主键。

### OrganizationMembership

代表“某用户/人员属于某社会团体”的关系：

```text
OrganizationMembership
├── membershipId
├── userId
├── personId
├── organizationId
├── roleId
├── dataScope
└── status
```

因此同一个用户可以加入多个社会团体：

```text
userId
  ↓
personId
  ├── Organization A → membership A
  ├── Organization B → membership B
  └── Organization C → membership C
```

### ExternalIdentity

用于保存外部身份映射：

```text
ExternalIdentity
├── identityId
├── userId
├── provider
├── providerSubject
└── status
```

例如未来可以同时支持不同登录方式，而不改变业务数据中的 `userId`。

## 3. 三端统一关系

```text
                  Identity Provider
                         │
                         ↓
                      userId
                         │
          ┌──────────────┼──────────────┐
          ↓              ↓              ↓
        Web           Android       HarmonyOS
          │              │              │
          └──────────────┼──────────────┘
                         ↓
                      Cloud DB
```

Web、Android、HarmonyOS 无论使用什么 SDK、登录界面或本地存储方案，最终都必须映射到同一个 `userId`。

## 4. 业务数据统一引用

所有涉及人员的业务对象统一使用 `userId` 记录系统身份：

```text
createdBy
updatedBy
ownerId
assigneeId
approverId
operatorId
```

示例：

```text
Project
├── ownerId = userId
└── updatedBy = userId

Approval
├── approverId = userId
└── createdBy = userId
```

需要自然人主档案时再关联 `personId`，需要组织成员关系时关联 `membershipId`。

## 5. 严禁作为业务主键的字段

以下字段不得作为 SmartSociety 的内部用户唯一主键：

- 手机号
- 邮箱
- 姓名
- 身份证件号码
- Android Device ID
- HarmonyOS Device ID
- Web 浏览器生成的 UUID
- 华为账号 ID / OpenID 等外部身份标识

原因：这些字段可能发生变化、可能一人多端、可能一人多身份，也可能随着身份提供商变化而失效。

## 6. userId 设计要求

`userId` 必须：

- 全局唯一
- 稳定
- 不可变
- 与设备无关
- 与客户端无关
- 与登录方式无关
- 不包含手机号等业务敏感信息
- 可以安全作为跨端业务关联字段

推荐使用随机生成的 UUID/ULID/同等级别的不可预测标识，不采用自增 ID 作为公开业务身份。

## 7. 组织上下文不能混入 userId

不要设计成：

```text
userId = organizationId + userId
```

组织关系必须通过：

```text
userId
   ↓
OrganizationMembership
   ↓
organizationId
```

这样才能支持多组织、组织切换、跨组织权限和组织成员生命周期管理。

## 8. 权限模型

统一采用：

```text
userId
  ↓
OrganizationMembership
  ↓
Role
  ↓
Permission
  ↓
DataScope
  ↓
OperationPolicy
```

客户端可以根据权限隐藏 UI，但真正的权限校验必须在 API Gateway / Cloud Functions / 后端服务执行。

## 9. 高风险身份操作

涉及以下操作时必须以 `userId` 为最终审计主体，并在服务端校验：

- 权限变更
- 角色变更
- 组织成员变更
- 治理任命
- 财务审批
- 决议审批
- 数据删除
- 重要数据恢复

审计至少保存：

```text
actorUserId
organizationId
action
targetType
targetId
occurredAt
sourceDevice
correlationId
```

## 10. 三端验收标准

同一个人在 Web 登录、Android 登录、HarmonyOS 登录后：

```text
Web.userId
   =
Android.userId
   =
HarmonyOS.userId
```

并且：

- 创建人一致
- 修改人一致
- 审批人一致
- 负责人一致
- 审计主体一致
- 组织成员关系一致
- 权限计算结果一致

这项规范属于 **P0，必须在三端正式开发前冻结**。
