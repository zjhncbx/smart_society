# 一、统一字段契约

所有核心业务对象（除 AppUser/UserSettings 等用户级对象外）必须包含：

```text
id orgId code status createdAt createdBy updatedAt updatedBy version sourceType sourceId
```

- `id`：对象主键（稳定，不随名称修改变化）
- `orgId`：组织隔离键（组织级对象必填）
- `code`：业务编码（如会员编码 M-0001、项目编码 P-2026-001），未启用的对象允许为空
- `status`：业务状态（对象语义不同，如 member/manual、project 0-3）
- `createdAt/createdBy/updatedAt/updatedBy`：审计四元组
- `version`：乐观锁版本（默认 1）
- `sourceType/sourceId`：数据来源（manual/dingtalk/system/auto + 来源对象）

流程对象额外增加：

```text
workflowInstanceId currentNode slaDeadline
```

风险对象额外增加：

```text
riskLevel riskSource riskScore ownerId deadline resolvedAt
```

事件对象额外增加：

```text
eventType entityType entityId actorId occurredAt metadata correlationId
```

# 三、统一事件契约（BusinessEvent）

```text
id orgId eventType entityType entityId entityName
actorId actorName level metadata sourceType sourceId correlationId
version isDeleted occurredAt createdAt
```

- `eventType`：created/submitted/approved/rejected/completed/updated/overdue/withdrawn/archived/deleted/status_changed/notified/resolved
- `correlationId`：一次业务动作（如一次提交）产生的一串事件的公共关联键，用于追踪“事件→规则→动作→新事件”链路
- ✅ 已贯通：业务动作生成关联键写入 BusinessEvent / AuditLog；AutoTask / RiskAlert / WorkItem 携带同一关联键；规则引擎与工作项物化按关联键可全链追踪

# 四、统一工作项契约（WorkItem，✅ 已落地）

Web 待办中心统一消费以下抽象，不再区分来源：

```text
WorkItem
 ├─ sourceType      # approval / auto_task / project_task / risk / data_quality / resolution / compliance
 ├─ sourceId        # 源对象 id
 ├─ title / description
 ├─ ownerId / ownerName
 ├─ priority        # low / medium / high
 ├─ status          # open / in_progress / done / cancelled
 ├─ deadline / slaDeadline
 ├─ escalationPolicy / escalationLevel
 └─ completionCondition
```

> 落地方式：WorkItem 表已建，`refresh-work-items` 从审批/自动任务/项目任务/风险/数据质量来源物化视图并自动关闭已消失项；`get-work-items` / `act-work-item` 供移动端与 Web 统一消费，详情仍指向源对象。

# 六、命名与编码约定

- 对象名：大驼峰；字段名：小驼峰；主键统一 `id`
- 组织主档主键：社会团体用统一社会信用代码，其余 `orgType_时间戳_随机`
- 业务编码：`{域缩写}-{年}-{序号}`，稳定不随名称变化（如 M-2026-0001）
- 云函数名：`{动作}-{对象}`（upsert-member / get-business-events / run-data-quality）
- 云函数返回：统一 `{ ret: { code, message, data } }`，`code=0` 成功
- 所有组织级写操作必须携带 `userId` 并做成员校验；管理员操作（组织关系/钉钉凭证/结账/审批流配置）校验 `role === 'admin'`

# 七、审计与可追溯约定

- 关键写入：AuditLog 记录 action/对象/操作人/改前改后/变更原因
- 业务变化：BusinessEvent 记录事件并带 correlationId
- 自动化：AutomationRunLog 记录规则命中、动作与耗时；RiskAlert/AutoTask 记录来源规则
- 全局可回答十问：谁发起、哪个组织、当前状态、谁负责、为何进入当前状态、发生了什么事件、依据什么规则、下一步、是否超时、是否闭环
