# 社易管 云存储安全策略（V1.0）

> 依据：docs/产品审视与优化路线.md（V6.0）、docs/云数据契约.md、docs/业务API契约.md
> 目的：冻结 AGC Cloud Storage 的桶安全规则、目录布局与服务端校验职责，杜绝"客户端直写任意路径"和"成员可读全组织文件"两类越权。
> 生效：本文为云存储安全规则唯一权威来源；修改规则必须先更新本文再部署。

---

# 一、默认策略的问题

AGC 云存储（CN）默认策略为：

```text
agc.cloud.storage[
  match: /{bucket}/{path=**} {
    allow read, write: if request.auth != null;
  }
]
```

问题：

1. **任意已登录用户可读写任意路径**：只要通过认证就能读写整个桶，无法表达"仅本人暂存区""组织共享区仅限成员"。
2. **安全规则无法查询 CloudDB**：规则引擎不能读取组织成员关系、角色、DataScope，因此"是否是本组织成员"这类判断**必须**在云函数中完成。
3. **文件名/路径可被枚举**：无前缀约束时，攻击者可遍历他人路径。

# 二、最终安全规则（推荐）

在 AGC 控制台 → 云存储 → 安全 → 配置策略 中粘贴：

```text
agc.cloud.storage[
  // 1) 默认拒绝：除下面显式放行的目录外，客户端一律禁止读写
  match /{bucket}/{path=**} {
    allow read, write: if false;
  }

  // 2) 用户私有暂存区：仅本人可读写自己的 _uploads/{userId} 目录
  match /{bucket}/_uploads/{userId}/{path=**} {
    allow read: if request.auth != null && request.auth.uid == userId;
    allow create, update, delete: if request.auth != null && request.auth.uid == userId;
  }
]
```

要点说明：

- 规则采用 **match + allow** 声明式语法；多条 `allow` 之间是 **OR** 语义（任一命中即放行）。
- `request.auth != null`：必须完成 AGC 认证（登录）才能操作。
- `request.auth.uid`：认证后的用户唯一标识，用于把目录绑定到当前登录者。
- `read` 可进一步细分为 `get` / `list`，`write` 可细分为 `create` / `update` / `delete`；上面的规则已按最小权限拆开。
- `{path=**}` 匹配目录及子路径；`{userId}` 是路径中的单段变量，规则内可直接引用。
- 如需限制文件大小/类型，可增加条件，例如：

```text
  match /{bucket}/_uploads/{userId}/{path=**} {
    allow create, update: if request.auth != null && request.auth.uid == userId
      && request.resource.size >= 1 && request.resource.size <= 10485760;
  }
```

> 注意：`request.resource.size` 单位是字节；示例为 1B ~ 10MB。是否启用由产品对附件大小的上限决定。

# 三、桶目录布局

```text
{bucket}
├── _uploads/{userId}/{documentId}      # 客户端 SDK 直传暂存区（规则只允许本人）
└── {orgId}/{domain}/{documentId}       # 组织共享区（客户端规则拒绝，仅云函数服务端访问）
```

约定：

- `documentId` 由云函数 `init-file-upload` 生成（随机不可预测），禁止客户端自定义文件名路径。
- `domain` 取值固定枚举：`member / project / notice / approval / finance / governance / attachment / other`，与 Document 对象的 `domain` 字段一致。
- 客户端**只能**写 `_uploads/{userId}/{documentId}`；组织共享区由云函数在服务端校验后写入。
- 云函数服务端读写不受客户端安全规则限制（规则只约束客户端 SDK）。

# 四、访问控制模型

## 4.1 客户端安全规则能做什么 / 不能做什么

| 能力 | 规则内 | 说明 |
|---|---|---|
| 是否已登录 | ✅ `request.auth != null` | |
| 目录归属当前用户 | ✅ `request.auth.uid == userId` | 用于 `_uploads/{userId}` |
| 文件大小/类型 | ✅ `request.resource.size/contentType` | |
| 是否本组织成员 | ❌ | 规则无法查询 CloudDB，必须云函数校验 |
| 角色 / 权限 / DataScope | ❌ | 同上 |

## 4.2 云函数校验链（所有文件动作必须走业务 API）

```text
客户端 → 统一业务 API（云函数）
  ├─ 校验：userId 有效性（AppUser）
  ├─ 校验：orgId + userId 成员关系（UserOrganization）
  ├─ 校验：domain 白名单
  ├─ 校验：DataScope / 角色（文件可见/可管范围）
  ├─ 强制 idempotencyKey（高风险写操作）
  ├─ 写 CloudDB Document 元数据
  ├─ 写 BusinessEvent + AuditLog（携带 correlationId）
  └─ 操作 Cloud Storage（服务端 SDK：校验存在性 → move / save / delete）
```

## 4.3 两种上传模式

| 模式 | 适用端 | 流程 |
|---|---|---|
| SDK 直传 | HarmonyOS / Android 移动端 | `init-file-upload` → 客户端 SDK 上传到 `_uploads/{userId}/{documentId}` → `commit-file-upload`（云函数校验并 move 到组织共享区） |
| 代理上传 | Web（统一 API Client） | `init-file-upload` → `commit-file-upload` 携带 `contentBase64`（限 5MB）→ 云函数服务端直接写入组织共享区 |

下载统一走 `get-document-file`（云函数服务端代理，返回 base64，限 10MB），保证组织共享区文件不暴露给客户端 SDK 直读。

# 五、云函数清单

| 函数 | 方法 | 幂等 | 说明 |
|---|---|---|---|
| `init-file-upload` | POST | ✅ 强制 key | 校验成员/domain，创建 Document(status=uploading)，返回 documentId + uploadPath |
| `commit-file-upload` | POST | ✅ 强制 key | 校验归属/大小，SDK 模式 move、代理模式 save，置 active，写事件+审计 |
| `list-documents` | POST | - | 校验成员，按 orgId/domain/refId/关键字分页，按 DataScope 返回 |
| `get-document-file` | POST | - | 校验可见性（成员+DataScope），服务端下载并返回 base64（≤10MB） |
| `delete-document` | POST | ✅ 强制 key | 校验 owner 或管理员，软删元数据 + 服务端删文件 |

# 六、部署与验证

1. **开通云存储**：AGC 控制台 → Serverless → 云存储，创建存储实例（默认桶名形如 `agc-cloudstorage-xxx`），将桶名配置到云函数环境变量 `CLOUD_STORAGE_BUCKET`（未配置时取默认值 `agc-cloudstorage`）。
2. **粘贴安全规则**：按第二节配置，先配置再上线，避免窗口期内客户端直写任意路径。
3. **云函数依赖**：涉及存储操作的函数（`commit-file-upload` / `get-document-file` / `delete-document`）依赖 `@agconnect/cloudstorage-server@1.0.1`；云函数运行时通过 `AGC_CONFIG`（自动注入的服务端凭据）初始化，无需在仓库提交任何密钥。
4. **验证用例（AGC 部署后）**：
   - 成员 A 上传 → 成员 B 无法通过客户端 SDK 读取 `_uploads/{userIdA}/...`；
   - 非组织成员调用 `get-document-file` 被拒；
   - `onlyMine/DataScope` 过滤后 `total` 口径正确；
   - 同 `idempotencyKey` 并发提交只产生一条 Document / 一次 move；
   - AuditLog / BusinessEvent 携带同一 `correlationId`。

# 七、已知限制与后续项

- **无短期签名 URL**：CN 云存储 Node.js Server SDK（1.0.1）不提供 signed URL，下载采用云函数代理（base64），因此单文件建议 ≤10MB；大文件需后续接入 OBS 预签名 URL 或 CDN。
- **客户端直传限本人暂存区**：组织共享区文件只有云函数能读写，客户端拿到的永远是"云函数签发的数据"而非桶路径，避免路径泄露。
- **删除为软删**：Document.status=deleted 后保留元数据供审计，存储文件由云函数删除；如需彻底清除元数据需另立治理任务。
- **桶级 CORS**：Web 代理模式不涉及桶级 CORS；若未来启用客户端直传 Web 上传，需在桶 CORS 配置中放行 `VITE_API_BASE_URL` 来源。
